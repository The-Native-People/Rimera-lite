Rimera supports a meaningful, growing subset of Python 3.12. It is not a
drop-in replacement for every Python application, package, or standard-library
module yet.

<Cards>
  <Card title="Everyday language features" description="Values, conditionals, loops, functions, closures, classes, inheritance, and exceptions." />
  <Card title="Collections and iteration" description="Strings, arbitrary integers, lists, tuples, ranges, dictionaries, sets, comprehensions, and for-loops." />
  <Card title="Native generators" description="Generator expressions plus supported source generators, send, throw, close, and yield from." />
  <Card title="Object behavior" description="Attributes, descriptors, slots, super, multiple inheritance, and the supported metaclass protocol." />
</Cards>

<Callout title="Use a focused entry point">
  Begin with the part of your application that has no external package or broad
  standard-library dependency. Run `rimlite --help`, then compile a small entry
  point first.
</Callout>

## Not available yet

<Cards>
  <Card title="Async programs" description="async, await, async generators, and async context managers are not available." />
  <Card title="General imports" description="The complete module, package, and sys.modules system is not available." />
  <Card title="Dynamic code" description="eval and exec are not available." />
  <Card title="Package ecosystems" description="Most stdlib modules and PyPI packages are outside the current supported surface." />
</Cards>

Unsupported behavior should fail clearly before Rimera writes a final artifact.
