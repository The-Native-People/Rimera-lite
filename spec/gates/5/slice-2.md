# Gate 5 Slice 2 — Function Identity, Metadata, Defaults, and Decorators

## Goal

Complete Python-visible function construction without moving broad inspection
APIs out of Gate 7.

## Integrated work

- Complete `__name__`, `__qualname__`, `__annotations__`, positional defaults,
  keyword defaults, closure ownership, and the code metadata required by the
  later reflection gate.
- Evaluate default expressions and decorators once, in Python order, with
  bottom-up decorator application and failure-atomic publication.
- Preserve mutable default identity, traced annotation/default graphs, nested
  qualified names, lambdas, methods, class-body functions, and comprehension
  boundaries.
- Route decorated and aliased functions through the ordinary generic call path;
  do not add compiler-only invocation shortcuts.
- Prove collection and heap-limit behavior for cycles involving functions,
  defaults, annotations, cells, classes, and bound methods.

## Implemented contract

- `FunctionObject` now owns traced live `defaults`, `keyword_defaults`, and `annotations` objects in addition to stable native code identity, name/qualified-name strings, parameter kinds, and closure cells. Per-parameter default snapshots were removed so one metadata source remains authoritative.
- `rimera_function_new` constructs positional defaults as one tuple and keyword-only defaults as one dictionary, roots both during construction, and publishes them only with the finished function object. `rimera_call`/`call::bind` reads the current metadata objects on every call, so legal `__defaults__`/`__kwdefaults__` mutation changes subsequent binding and replaced values can be collected.
- Ordinary attribute get/set/delete exposes CPython-shaped `__name__`, `__qualname__`, `__defaults__`, `__kwdefaults__`, and lazy `__annotations__` behavior with managed `TypeError` preservation. No compiler-only metadata accessor or invocation shortcut was added.
- Module, nested, class-body method, lambda, and comprehension-boundary qualified names are generated by the normal lowering context. Ordinary `def` decorators are preserved by sema, decorator expressions evaluate top-to-bottom before defaults/annotations, applications run bottom-up, and the target binding is published only after successful decoration.
- The generic `MakeFunction -> rimera_function_new -> rimera_call` path remains the only compiled function path. Function/default/annotation/cell graphs and instance/bound-method cycles are traced through the normal GC graph.

## Completion proof

- The Slice 1 syntax/sema/MIR ownership tests verify that the metadata and decorators reach the existing `MakeFunction`/ordinary call path rather than a parallel representation.
